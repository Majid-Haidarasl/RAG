هستهٔ RAG سلسله‌مراتبی آفلاین · مطالعهٔ موردی **آرمان‌رایان** · ایشو #۷ گیت‌هاب · پرونده مرجع: **آذرپخش** (AR-ISS-024).

این بسته روی فاز ۶ سوار می‌شود و بافت `issues` فاز ۳ را گسترش می‌دهد. وابستگی تازه‌ای اضافه نشده است. تست‌ها به Ollama، GPU یا اینترنت نیاز ندارند.

## اجرا روی اوبونتو

فرض: zip در `~/Downloads/rag-phase-07.zip` است و کلون ریپو در `~/Desktop/RAG` (یا هر پوشه‌ای که ریپو را در آن کلون کرده‌اید).

```bash
cd ~/Downloads
unzip -o rag-phase-07.zip -d ~/Desktop/RAG
cd ~/Desktop/RAG
bash scripts/setup_and_test.sh
```

ترتیب اجرا: `pytest`، ورود پیکره، چرخهٔ عمر و تکرار (فاز ۵)، سلسله‌مراتب (فاز ۶)، سپس بررسی مسئله‌ها. آخرین بلوک بین دو خط `======== PHASE 7 SUMMARY` چاپ می‌شود و شمار تست‌ها، آمار مسئله‌ها و نتیجهٔ PASS/FAIL را دارد. عددهای بخش «نتیجه» از همین بلوک برداشته می‌شوند.

اجرای جدا:

```bash
source .venv/bin/activate

python scripts/run_issue_check.py
```

## چه چیزی ساخته شد

- **مدل مسئله:** ریشهٔ تجمیع `Issue` با فراداده:
  - گره گزارش‌دهنده، گره مالک و گره‌های درگیر؛
  - اسناد مرتبط (مثل AR-ISS-024)، شمارهٔ قرارداد (AR-CNT-1402-118)؛
  - دسته، شدت، اولویت P1 تا P4، تاریخ‌ها و برچسب‌ها.
- **زیرمسئله:** موجودیت `SubIssue` با شناسهٔ `والد/کد` (مثل `AR-ISS-024/WIN`)، مالک، گره‌های پشتیبان، وابستگی به زیرمسئلهٔ دیگر و مجریان.
- **وضعیت‌ها:**
  - هفت وضعیت: باز، بررسی‌شده، در جریان، مسدود، حل‌شده، بسته، بازگشایی‌شده؛
  - گذارها با ماشین حالت کنترل می‌شوند؛
  - چهار دستهٔ وضعیت: انجام‌نشده، فعال، منتظر، تمام‌شده؛
  - نام‌های وضعیت فاز ۳ همچنان پذیرفته می‌شوند.
- **قواعد:**
  - والد تا وقتی زیرمسئلهٔ باز دارد حل یا بسته نمی‌شود؛
  - زیرمسئلهٔ والدِ بسته یا نامعتبر تغییر نمی‌کند؛
  - زیرمسئله پیش از وابستگی‌اش حل نمی‌شود؛
  - وابستگی‌ها حلقه ندارند؛
  - همهٔ گره‌ها باید در ثبت فاز ۶ باشند.
- **جایگاه نسبی:**
  - لایه و عمق مالک، و محلی یا بین‌واحدی بودن مسئله؛
  - مقصد ارجاع با منطق ارجاع فاز ۶؛
  - این اطلاعات از راه درگاه `OrgDirectory` و لایهٔ ضدفساد (ACL) گرفته می‌شود؛ بافت مسئله مستقیم به سلسله‌مراتب وابسته نیست.
- **مقایسه با مسئله‌های موجود** (`comparison.py`):
  - شباهت متن روی توکن‌های نرمال‌شدهٔ فارسی و انگلیسی؛
  - هم‌پوشانی فراداده: گره، سند، دسته و قرارداد؛
  - برچسب تکراری، مرتبط یا تازه با آستانه‌های مستند؛
  - درگاه embedding برای بعد آماده است، ولی Ollama صدا زده نمی‌شود.
- **تولید زیرمسئله:** تجزیه‌گر قاعده‌محور مسئلهٔ آذرپخش را به چهار زیرمسئله می‌شکند:

  | زیرمسئله | مالک |
  |---|---|
  | سخت‌افزار (کنترلر RAID و RAM) | N-HW-REP |
  | کلاینت ویندوزی و درایور | N-SW-WIN |
  | تأخیر گزارش‌گیری وب | N-SW-WEB |
  | قرارداد و زمان تحویل | N-ADM-LEG |

  درگاه تجزیه‌گر LLM اختیاری است و در تست‌ها استفاده نمی‌شود.
- **داده:** `data/issues/` شامل پرونده آذرپخش و شش مسئلهٔ ساختگیِ برگرفته از پیکره، به‌علاوهٔ چهار نمونهٔ ورودی تازه.
- **اصلاح جانبی:** رشتهٔ نسخه در اسکریپت‌های فاز ۴ تا ۶ حالا از `rag_core.__version__` خوانده می‌شود و دیگر کهنه نمی‌ماند.
