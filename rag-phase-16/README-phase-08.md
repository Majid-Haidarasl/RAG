# فاز ۸ — هستهٔ بازیابی RAG و پرسش‌وپاسخ (نسخهٔ ۰.۸.۰)

هستهٔ RAG سلسله‌مراتبی آفلاین · مطالعهٔ موردی **آرمان‌رایان** · ایشو #۸ گیت‌هاب · پرونده مرجع: **آذرپخش** (AR-ISS-024).

این بسته روی فاز ۷ سوار می‌شود و بافت‌های `rag` و `qa` را می‌سازد: بازیابی ترکیبی BM25 و برداری، محدود به دامنهٔ گره پرسش‌کننده، چیدن متن زمینه با بودجهٔ توکن، و پاسخ با ارجاع اجباری. همه‌چیز آفلاین است و فقط با Ollama محلی (`http://localhost:11434`) کار می‌کند. تست‌ها با جایگزین‌های ساختگی اجرا می‌شوند و به Ollama، GPU یا اینترنت نیاز ندارند.

تنها وابستگی تازه `PyYAML` است (برای خواندن پرامپت‌ها و تنظیمات YAML).

## سیستم هدف

- Ubuntu 24.04.5 LTS، پایتون 3.12.3؛
- دست‌کم ۱۶ گیگابایت RAM؛
- کارت گرافیک NVIDIA با ۱۲ گیگابایت حافظه (فقط مرحلهٔ زندهٔ Ollama از GPU استفاده می‌کند)؛
- مسیر پروژه `~/Desktop/RAG`.

اندازهٔ دسته‌های embedding (۱۶)، بودجهٔ متن زمینه (۳۵۰۰ توکن)، `num_ctx` (۸۱۹۲) و مهلت‌ها (embedding ۱۲۰ ثانیه، تولید ۲۴۰ ثانیه) برای همین سیستم تنظیم شده‌اند.

## پیش‌نیاز مرحلهٔ زنده

مرحلهٔ زنده فقط وقتی اجرا می‌شود که Ollama روشن باشد و هر دو مدل نصب باشند:

```bash
ollama list
```

در فهرست باید `bge-m3:latest` و `qwen3:8b` دیده شوند. اگر نبودند:

```bash
ollama pull bge-m3
ollama pull qwen3:8b
```

اگر Ollama یا یکی از مدل‌ها نباشد، مرحلهٔ زنده با وضعیت `skipped` گزارش می‌شود و نتیجهٔ PASS/FAIL را تغییر نمی‌دهد.

## اجرا روی اوبونتو

فرض: zip در `~/Downloads/rag-phase-08.zip` است و کلون ریپو در `~/Desktop/RAG` (یا هر پوشه‌ای که ریپو را در آن کلون کرده‌اید).

```bash
cd ~/Downloads
unzip -o rag-phase-08.zip -d ~/Desktop/RAG
cd ~/Desktop/RAG
bash scripts/setup_and_test.sh
```

ترتیب اجرا: `pytest`، ورود پیکره (فاز ۴)، چرخهٔ عمر و تکرار (فاز ۵)، سلسله‌مراتب (فاز ۶)، بررسی مسئله‌ها (فاز ۷)، سپس مرحلهٔ RAG فاز ۸. بار اول ساخت نمایهٔ برداری چند دقیقه طول می‌کشد؛ اجراهای بعدی فقط تکه‌های تازه یا تغییرکرده را دوباره embed می‌کنند.

آخرین بلوک بین دو خط `======== PHASE 8 SUMMARY` چاپ می‌شود. این بلوک شمار تست‌ها، وضعیت مراحل قبلی، نام مدل‌ها، آمار نمایه، زمان ساخت نمایه، وضعیت مرحلهٔ زنده (`ok` / `skipped` / `fail`) و شاخص‌های آن را دارد. عددهای بخش «نتیجه» از همین بلوک برداشته می‌شوند.

اجرای جدا:

```bash
source .venv/bin/activate
pytest -m "retrieval or qa"
python scripts/run_rag_demo.py            # بررسی آفلاین + مرحلهٔ زنده
python scripts/run_rag_demo.py --no-live  # فقط بررسی آفلاین
python scripts/run_rag_demo.py --rebuild  # ساخت دوبارهٔ کامل نمایه
```

## چه چیزی ساخته شد

- **نمایه:**
  - هر تکه از فاز ۴ با نسخه و وضعیت چرخهٔ عمر فاز ۵، گره مالک و لایه، ردهٔ دانش و ارجاع منبع (صفحه یا پاراگراف و عنوان بخش) ثبت می‌شود؛
  - نمایهٔ پایدار SQLite در `.rag-index/phase-08.sqlite` با به‌روزرسانی افزایشی؛
  - نسخه‌های بازنشسته نگه داشته می‌شوند ولی هرگز بازیابی نمی‌شوند.
- **بازیابی:**
  - فقط اسناد قابل‌دیدن برای گره پرسش‌کننده (درگاه دامنهٔ فاز ۶ از راه لایهٔ ضدفساد)؛
  - فیلتر زبان، شناسهٔ سند، لایه، ردهٔ دانش و فقط نسخه‌های فعال؛
  - BM25 روی توکن‌های نرمال‌شدهٔ فارسی و انگلیسی، و شباهت کسینوسی bge-m3؛
  - ادغام دو فهرست با RRF (k=60)؛
  - حذف تکه‌های تکراری و نزدیک‌به‌تکرار با اطلاعات فاز ۵.
- **متن زمینه:** بودجهٔ ۳۵۰۰ توکن، ترتیب بر پایهٔ رتبه و ترتیب تکه‌ها در سند، و برچسب منبع مثل `[AR-HR-005 §12]` با شناسهٔ سند، نسخه و پاراگراف.
- **پرسش‌وپاسخ:**
  - پاسخ به زبان پرسش، با ارجاع اجباری `[شناسهٔ سند §بخش]`؛
  - ارجاع‌ها تجزیه و با متن زمینه سنجیده می‌شوند؛
  - پاسخ ساختاریافته: وضعیت، متن، ارجاع‌های معتبر و نامعتبر، تکه‌های استفاده‌شده، زمان‌ها؛
  - چهار وضعیت: پاسخ داده شد، زمینهٔ ناکافی، در دامنه پیدا نشد، بیرون از دامنه؛
  - برای پرسش بیرون از دامنه، ارجاع به نیای مشترک با منطق فاز ۶، بدون نشان دادن متن اسناد بیرون از دامنه.
- **بررسی پایهٔ واقعیت:** شناسه‌ها و عددهای پاسخ باید در تکه‌های ارجاع‌شده باشند؛ در غیر این صورت پرچم می‌خورند.
- **مدل‌ها:** `bge-m3:latest` برای embedding و `qwen3:8b` با دمای ۰٫۲ و حالت تفکر خاموش برای تولید. نام مدل‌ها و نشانی Ollama در `config/rag.yaml` است.
