# هستهٔ RAG سلسله‌مراتبی و آفلاین آرمان‌رایان، نسخهٔ ۱.۰.۰

این پروژه یک سامانهٔ **پرسش و پاسخ روی اسناد سازمان** است که به‌طور کامل روی یک رایانهٔ محلی و بدون اینترنت کار می‌کند.
مدل‌های زبانی با `Ollama` روی همان رایانه اجرا می‌شوند؛ مدل `qwen3:8b` متن را تولید می‌کند و مدل `bge-m3` متن را به بردار تبدیل می‌کند.
مطالعهٔ موردی، شرکتی فرضی به نام **آرمان‌رایان** است که ۲۶ سند فارسی، ۲۶ سند انگلیسی، ساختار سازمانی، ایشوها، پروژه‌ها، درخواست‌های پیشنهاد و پیشنهادها دارد.

## سامانه چه کاری انجام می‌دهد

- اسناد با قالب `DOCX`، `DOC` و `PDF` را می‌خواند، آن‌ها را به تکه‌های کوچک‌تر تقسیم می‌کند و نسخه‌ها و تکراری‌ها را مدیریت می‌کند.
- دانش را در **سلسله‌مراتب سازمان**، یعنی لایه‌ها و گره‌ها، نگه می‌دارد و هر پرسش فقط در محدودهٔ همان گره جست‌وجو می‌شود.
- با جست‌وجوی ترکیبی، یعنی `BM25` همراه با بردار متن، پاسخ می‌دهد و در پاسخ **به منبع ارجاع** می‌دهد.
- ایشوها و زیرایشوها را با دانش موجود مقایسه می‌کند و مجری مناسب را پیشنهاد می‌دهد.
- یک **داور** قاعده‌ای و یک داور مبتنی بر مدل، کیفیت خروجی‌ها را می‌سنجند.
- بستهٔ انتقال دانش، گزارش پروژه، اولویت ایشوهای کلیدی، سند درخواست پیشنهاد و ارزیابی پیشنهادها را می‌سازد.
- پرامپت‌ها و تنظیمات را با یک مجموعهٔ مرجع دوزبانه می‌سنجد و بهترین گزینه را انتخاب می‌کند.

## شروع سریع

فرمان‌های زیر برای سیستم‌عامل `Ubuntu` است:

</div>

```bash
sudo apt install -y python3 python3-venv git unzip curl libreoffice-writer poppler-utils
curl -fsSL https://ollama.com/install.sh | sh
ollama pull bge-m3 && ollama pull qwen3:8b
cd ~/Desktop/RAG
bash scripts/setup_and_test.sh
```

<div dir="rtl">

روی `Windows 11`، اسکریپت با `bash` نوشته شده و باید داخل `Ubuntu` و روی `WSL 2` اجرا شود؛ `Git Bash` برای این کار کافی نیست.
در این حالت، نسخهٔ ویندوزی `Ollama` نصب می‌شود و با حالت شبکهٔ `mirrored` از داخل `WSL` روی نشانی `localhost:11434` در دسترس است.
بقیهٔ فرمان‌ها همان فرمان‌های `Ubuntu` است.

اسکریپت یک محیط مجازی `.venv` می‌سازد، پروژه را نصب می‌کند، همهٔ تست‌های واحد را با سنجش پوشش کد اجرا می‌کند و سپس بررسی‌های فاز ۴ تا ۱۶ را به ترتیب انجام می‌دهد.
آخرین بلوک خروجی با عنوان `PHASE 16 SUMMARY` چاپ می‌شود و مقدار وضعیت در آن باید `status: PASS` باشد.
اگر `Ollama` در دسترس نباشد، مرحله‌های زنده اجرا نمی‌شوند و فقط در گزارش ثبت می‌شوند؛ قبول‌شدن بررسی‌ها به این مرحله‌ها وابسته نیست.

راهنمای کامل نصب و اجرا در فایل [`docs/user-guide.md`](docs/user-guide.md) آمده است.

## ساختار پوشه‌ها

| پوشه | محتوا |
|---|---|
| `src/rag_core/` | کد اصلی؛ برای هر بافت دامنه یک بستهٔ پایتون جداگانه |
| `tests/unit/` | تست‌های واحد که به `Ollama`، کارت گرافیک یا اینترنت نیاز ندارند |
| `scripts/` | اسکریپت اجرای کامل و بررسی هر فاز |
| `config/` | تنظیمات هر بخش با قالب `YAML` و پرامپت‌ها |
| `corpus/` | اسناد نمونهٔ فارسی و انگلیسی آرمان‌رایان |
| `data/` | ثبت لایه‌ها، گره‌ها، ایشوها، پروژه‌ها، درخواست‌های پیشنهاد و مجموعه‌های داوری |
| `eval/` | مجموعهٔ مرجع پرسش و پاسخ، نتیجه‌های ارزیابی و فهرست شواهد |
| `docs/` | مستندات هر فاز، مستندات فنی، راهنمای کاربر و گزارش نهایی |
| `presentation/` | اسلایدهای معرفی و متن دموی زنده |
| `training/` | مطالب آموزشی برای عضو تازهٔ تیم |
| `results/`، `exports/` | خروجی‌های هر اجرا که در مخزن نگه داشته نمی‌شوند |

## سیستم اندازه‌گیری

عددهای گزارش روی سیستم مرجع با `Fedora Linux`، `Python 3.15.2` و `Ollama 0.40.17` اندازه‌گیری شده‌اند.
مشخصات کامل این سیستم در بخش ۲ فایل [`docs/final-report.md`](docs/final-report.md) آمده است.
نصب و اجرا روی `Ubuntu` و `Windows 11` با `WSL 2` در فایل [`docs/user-guide.md`](docs/user-guide.md) توضیح داده شده است.

## دربارهٔ داده‌ها

اسناد پوشهٔ `corpus/` ساختگی هستند و فقط برای آزمایش این سامانه نوشته شده‌اند.
نام‌ها، عددها و شناسه‌های این اسناد واقعی نیستند.
